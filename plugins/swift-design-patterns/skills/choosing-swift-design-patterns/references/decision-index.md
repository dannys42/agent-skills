# Swift Design Pattern Decision Index

Use this index only after identifying a concrete design pressure. Prefer no
change or the listed Swift-native alternative when it remains clearer. Load at
most two linked pattern references before recommending an approach.

| Pressure or symptom | Consider first | Pattern when pressure persists | Avoid when | Reference |
|---|---|---|---|---|
| Several products must switch as one compatible family. | Generic configuration or injected closures | Creational · Abstract Factory when clients must not mix family members. | One product varies, or a small composition-root switch is exhaustive. | [Abstract Factory](creational/abstract-factory.md) |
| Construction has staged inputs, validation, or reusable recipes. | Initializer defaults or a configuration value; a result builder only for declarative nested content. | Creational · Builder when explicit `build()` protects invariants or resolves a complex result. | Calls merely assign properties, or a result builder would hide fallible or order-dependent validation. | [Builder](creational/builder.md) |
| A stable workflow must vary creation of one product. | Direct initializer or injected creation closure | Creational · Factory Method (virtual constructor) when creators need replaceable construction behavior. | One known type suffices, or products must vary as a family. | [Factory Method](creational/factory-method.md) |
| Callers need independent variants of an expensive prepared reference graph. | Struct copy and copy-on-write values | Creational · Prototype when deep-copy semantics must preserve internal graph relationships. | Values already copy correctly, or reconstruction is cheap and explicit. | [Prototype](creational/prototype.md) |
| Process-wide identity is an actual invariant. | Dependency injection or explicit environment value | Creational · Singleton when construction and identity must be globally controlled. | Global reachability is merely convenient, state needs scoping, or tests need isolation. | [Singleton](creational/singleton.md) |
| External or legacy semantics do not match the local interface. | Extension or small conversion function | Structural · Adapter when a durable boundary must translate interface and meaning. | You control both APIs, or direct conversion stays obvious. | [Adapter](structural/adapter.md) |
| Two independent variation axes create a growing cross-product. | Generic parameter or protocol composition | Structural · Bridge when both axes must evolve or switch independently. | Only one axis varies, or compile-time composition removes duplication. | [Bridge](structural/bridge.md) |
| Clients should treat leaves and nested groups uniformly. | `indirect enum` for a closed tree | Structural · Composite when an open hierarchy needs recursive uniform operations. | Node kinds are closed, or leaves and containers have misleadingly different behavior. | [Composite](structural/composite.md) |
| Optional responsibilities must stack around one stable interface. | Closure composition, protocol extension, or property wrapper | Structural · Decorator (wrapper) when layers need runtime ordering and independent composition. | One wrapper suffices, or the concern is access control rather than added behavior. | [Decorator](structural/decorator.md) |
| Clients repeatedly coordinate a complicated subsystem workflow. | Focused service with direct composition | Structural · Facade when one stable entry point should hide subsystem choreography. | The wrapper only forwards calls, or clients need the subsystem’s full flexibility. | [Facade](structural/facade.md) |
| Huge object counts duplicate immutable intrinsic data. | Shared immutable value and cache | Structural · Flyweight when measured memory pressure justifies keyed sharing. | Object counts are modest, state is mutable, or profiling shows no material saving. | [Flyweight](structural/flyweight.md) |
| Access to a subject needs uniform authorization, laziness, transport, or auditing. | Direct authorization gate, lazy closure, actor cache for caching, or explicit transport/audit boundary | Structural · Proxy (surrogate) when a stand-in must preserve the subject contract and govern access. | The wrapper merely adds optional behavior, or it hides latency behind a synchronous API. | [Proxy](structural/proxy.md) |
| Ordered handlers may consume, reject, or pass a request onward. | Array of closures or validation functions | Behavioral · Chain of Responsibility (CoR) when dynamic handlers decide continuation. | Every rule has the same shape, always runs, or forms a fixed short loop. | [Chain of Responsibility](behavioral/chain-of-responsibility.md) |
| An operation needs identity for undo, queueing, logging, or replay. | Closure or `UndoManager` registration | Behavioral · Command when operation data and lifecycle outgrow an opaque closure. | Invocation is immediate and no history or inspection is required. | [Command](behavioral/command.md) |
| A custom collection needs traversal independent of storage. | `Sequence`, `IteratorProtocol`, or `AsyncSequence` | Behavioral · Iterator (cursor) when custom traversal state or policy must remain encapsulated. | An existing collection already exposes safe traversal, or async adds no real suspension. | [Iterator](behavioral/iterator.md) |
| Several peers form a web of interaction rules. | Coordinator closure or shared observable model | Behavioral · Mediator when cross-participant policy needs one explicit home. | Participants only share state, or one parent-child callback is enough. | [Mediator](behavioral/mediator.md) |
| Undo or rollback needs an invariant-preserving state capture. | Ordinary value snapshot; `Codable` only when serialization or durability is required. | Behavioral · Memento (snapshot) when the originator must control capture and restoration internals. | The public value can simply be stored, or durable persistence is the real requirement. | [Memento](behavioral/memento.md) |
| Multiple subscribers need domain-specific delivery and registration semantics. | Observation, `AsyncStream`, or direct callback | Behavioral · Observer (listener) when native tools lack needed one-to-many semantics. | One dependency is clearer, or events require centralized coordination. | [Observer](behavioral/observer.md) |
| Behavior and transitions vary with an object’s lifecycle state. | Enum plus exhaustive switch | Behavioral · State when distributed branches and state-specific behavior obscure the lifecycle. | A small closed switch remains readable, or callers select independent algorithms. | [State](behavioral/state.md) |
| An algorithm must vary behind one stable operation. | Closure or generic algorithm parameter | Behavioral · Strategy (policy) when alternatives own state, dependencies, tests, or runtime substitution. | Variants are tiny fixed formulas, or behavior changes through lifecycle transitions. | [Strategy](behavioral/strategy.md) |
| Variants must preserve one ordered algorithm while changing selected steps. | Protocol extension and composition | Behavioral · Template Method when the invariant pipeline needs enforced extension points. | Steps need arbitrary reordering, or the whole algorithm swaps as a unit. | [Template Method](behavioral/template-method.md) |
| A stable element hierarchy gains many type-specific operations. | Enum switch or protocol extension | Behavioral · Visitor when new operations arrive more often than new element kinds. | Element types evolve frequently, or an exhaustive switch is still compact. | [Visitor](behavioral/visitor.md) |

## Commonly confused choices

| Choices | Distinguishing pressure |
|---|---|
| Factory Method / Abstract Factory / Builder | Vary creation of one product / create a compatible product family / assemble one validated result in stages. |
| Adapter / Bridge / Facade | Translate an existing incompatible boundary / separate two planned variation axes / simplify a subsystem workflow for clients. |
| Decorator / Proxy | Stack optional behavior / stand in for a subject to control access. |
| State / Strategy | Lifecycle transitions select behavior internally / a caller or configuration selects an algorithm. |
| Observer / Mediator | Broadcast change to independent subscribers / centralize interaction rules among collaborating peers. |
